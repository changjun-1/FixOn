## 이번 브라우저 확인

서비스용 회원 비밀번호를 변경하지 않고, 3100번 검증 서버와 전용 테스트 DB로 확인했습니다.

1. 일반 아이디 로그인 실패 안내, 테스트 관리자 정상 로그인
2. 분리한 관리 화면 스크립트로 신고 목록·필터·상태 변경 폼 표시
3. 상태 변경 저장 후 상세 화면에 관리자·시각·접수 → 확인 이력 표시
4. 시설 수정 폼에 기존 값 표시
5. 검색 결과 0건 안내, 없는 신고 오류 안내
6. 로그아웃 후 로그인 화면으로 이동
7. 1100×560 화면에서 로그아웃 버튼 전체 노출, 메뉴만 스크롤
8. 390×844 화면에서 상세·처리 이력 표시, 문서 가로 넘침 없음

브라우저 캡처: [모바일 처리 이력](screenshots/history-mobile.png), [낮은 화면 로그아웃](screenshots/sidebar-short-height.png).

## 한계

- 카카오·Google 개발자 콘솔과 `.env` 키 연결은 완료했습니다.
- 실제 제공자 계정의 최종 동의와 앱 콜백 성공은 아직 확인하지 않았습니다.
- 외부 배포·운영 부하·모든 브라우저/기기 호환성은 검증하지 않았습니다.
- 이미지 업로드 대신 선택적 HTTP/HTTPS 이미지 URL을 사용합니다.
- 로컬 세션 기본값은 메모리이고 SQL 저장소는 환경변수로 선택합니다.
- 이력 도입 전 데이터는 소급 기록하지 않습니다.
- 이력은 법적 감사 로그가 아니며, DB 직접 수정은 기록하지 않고 신고 삭제 시 함께 삭제됩니다.

교수님 step5 구조 전환 후 app.js 직접 실행으로 Passport 로그인 → 신고 목록 조회 → 로그아웃을 브라우저에서 확인했습니다. 캡처는 screenshots/passport-structure-check.png입니다.


## 로그인·작업 화면 디자인 정리

SupremeNote 저장소의 색감과 여백을 참고해 FixOn 화면에 적용했습니다.
로그인·회원가입도 내부 작업 화면과 같은 밝은 중립색의 중앙 카드로 구성하며 업무 메뉴를 렌더링하지 않습니다.
로그인 후에는 밝은 작업 화면과 SVG 아이콘 메뉴를 표시합니다.
자동 테스트는 로그인 전 메뉴 비노출과 로그인 후 노출, 로그인 회원의 인증 화면 리다이렉트를 검증합니다.
브라우저에서 1440×900 데스크톱, 390×844 모바일, 높이 560px의 로그아웃 노출을 확인했습니다.
모바일 대시보드의 표는 표 영역만 가로 스크롤하며 문서 전체의 가로 넘침은 없습니다.
최종 밝은 작업 화면 캡처: screenshots/workspace-light-final.png. 초기 로그인 시안 캡처는 이전 디자인의 기록입니다.
