# FixOn 테스트 결과

검증일: 2026-10-31 (한국 시간)

## 환경

- Windows, Node.js 24.21.0, npm 11.19.0
- MySQL Community Server 8.4.13, 로컬 포터블 실행
- 검증 서버 포트 33306 (일반 실행 예시는 3306)
- 실행 DB fixon, 테스트 DB fixon_test
- Jest + Supertest, 실제 MySQL + Sequelize

개발 PC에 MySQL Server가 없어서 작업 폴더에 공식 ZIP 배포본을 준비해 실행했다. 시스템 서비스 설치나 기존 DB 변경은 하지 않았다. 포터블 MySQL 실행 파일·데이터·검증용 비밀번호는 제출 프로젝트에 포함하지 않는다.

| 합계 | 36 | 통과 36 / 실패 0 |

```text
Test Suites: 5 passed, 5 total

Snapshots:   0 total
```

서비스·테스트 접속 환경 변수를 지정한 상태에서 `node node_modules/jest/bin/jest.js --runInBand --json`으로 실행했고, 개발 복사본에서 README의 `npm test` 명령으로도 36개 전체 통과를 확인했다. 개발 검증용 래퍼는 환경 변수만 주입하며 테스트 코드를 변경하지 않는다. JSON 실행 결과의 요약은 test-summary.json에 포함했다.

`npm run check`로 모든 JavaScript의 `node --check` 구문 검사도 통과했다. bcrypt 해시 생성과 Sequelize 모델 초기화도 실행 확인했다.

### 주요 검증

- 신고 저장 후 실제 DB 조회, 서버가 작성자·최초 상태 지정
- 입력 오류·없는 대상·다른 회원 접근·관리자 권한 검사
- 검색·필터·페이지네이션·통계
- 시설·분류 참조 중 삭제 제한, 비활성 분류 신고 거절
- 시설별 정비 이력에 다른 시설의 작업이 포함되지 않음
- 담당자 검증, 중복 작업 생성 거절, 동시 생성 시 하나만 성공
- 잘못된 상태 전이와 완료 결과 누락 거절
- 완료 시 작업·신고 상태 동기화, 기한 초과에서 종료 작업 제외
- CSRF 없는 변경 차단, 회원 가입 요청의 ADMIN 역할 무시
- 주요 화면 HTML 렌더링, 회원 응답의 비밀번호 비노출

## 브라우저 검증

로컬 앱을 실제 브라우저에서 조작해 확인했다.

1. admin 로그인, 대시보드·최근 신고 표시
2. 신고에서 정비 작업 생성, 기한 입력, 목록 반영
3. student 담당자 배정 → IN_PROGRESS → 처리 결과 입력 → COMPLETED
4. 신고 상세에서 RESOLVED 및 처리 결과 표시
5. 관리자 시설 등록 후 목록 반영
6. 분류 목록 조회
7. 로그아웃 후 student 로그인, 관리자 메뉴가 표시되지 않음
8. 일반 사용자의 새 신고 등록 후 목록 반영
9. Node 서버 재시작 후 다시 로그인하여 기존 신고·정비 완료 데이터 유지 확인

검증 스크린샷은 screenshots/ 폴더에 저장했다. 화면 캡처는 회의 인증 사진을 대체하지 않는다.

## 범위와 한계

- 모든 브라우저·모바일 기기의 호환성을 검증한 것은 아니다.
- 이미지 업로드 대신 선택적 이미지 URL을 사용한다.
- 외부 인터넷 배포·운영 환경·부하 테스트는 수행하지 않았다.
- 세션 저장소는 로컬 시연용 메모리 저장소다.
- 교수님 지정 보고서 양식과 실제 대면 회의 사진은 제공되지 않아 최종 보고서 PDF는 만들지 않았다.
